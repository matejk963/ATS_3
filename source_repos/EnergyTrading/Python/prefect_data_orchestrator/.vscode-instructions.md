# Prefect Data Orchestrator Instructions

## Project Context
- **Prefect Version**: 3.1.11 (LOCKED - do not upgrade)
- **Platform**: Windows 11 with Conda environments
- **Execution Strategy**: Conda environments for isolation (faster than Docker/venv)
- **Server**: Remote Prefect server running on Windows 11 via `python register_flows.py` in conda development environment
- **Architecture**: Multi-machine setup - development on macOS, orchestration on remote Windows 11

## Core Architecture Principles

### Work Pool Strategy
- Each work pool is linked to a specific conda environment
- Use `conda run -n <env_name> python -m prefect.engine` as the command template
- Conda environments provide faster execution isolation than containers
- Environment visibility allows easy package management inspection

### Deployment Lifecycle Management
- **Clean Slate Approach**: Always delete existing deployments before recreating
- **Process Management**: Proper lifecycle management of server/worker processes
- **Resource Cleanup**: Ensure ports, processes, and work pools are properly managed
- **Error Recovery**: Implement fallback mechanisms for failed deployments

## Configuration Standards

### Environment Configuration
```python
WORK_POOL_NAME = "conda-develop"
PREFECT_API_URL = "http://127.0.0.1:4200/api"
CONDA_ENV_NAME = "develop"
```

### Scheduling Standards
- Use `CronSchedule` with explicit timezone: `timezone='Europe/Berlin'`
- Align schedules with market data availability windows
- Spot data: 13:15 and 15:50 CET (after market close)
- COT data: Tuesday 08:25 CET (after CFTC release)

## Import Standards
- Follow absolute imports from project root: `from Database.TPData import something`
- Access other project modules: `from Utilities.Storage import something`
- Internal orchestrator imports: `from prefect_data_orchestrator.flow_spot_daily import spot_daily`

## Process Management Requirements

### Server Lifecycle
1. **Stop existing server**: Check port 4200, terminate processes gracefully
2. **Force cleanup**: Use `taskkill /F /IM prefect.exe` if needed
3. **Start fresh**: Launch in new terminal with conda environment
4. **Validation**: Ensure port availability before proceeding

### Worker Management
1. **Stop all workers**: Kill existing worker processes
2. **Reset work pools**: Delete and recreate with `--overwrite`
3. **Launch workers**: Start in separate terminal with PYTHONPATH set
4. **Environment isolation**: Each worker uses dedicated conda environment

### Deployment Management
1. **Clean deployments**: Delete all existing deployments
2. **Register flows**: Deploy with proper scheduling and parameters
3. **Validation**: Verify deployments are active and scheduled
4. **Monitoring**: Track deployment status and execution

## Error Handling Standards

### Process Termination
```python
try:
    proc.terminate()
    proc.wait(timeout=5)
except (psutil.NoSuchProcess, psutil.AccessDenied, psutil.ZombieProcess):
    pass
```

### Port Management
```python
def is_port_in_use(port):
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
        return s.connect_ex(("127.0.0.1", port)) == 0
```

## Windows-Specific Considerations

### Terminal Management
- Use `start cmd /k` for persistent terminal windows
- Activate conda environment before running commands
- Set PYTHONPATH for module resolution
- Use `taskkill` for force process termination

### Path Handling
- Use absolute paths for SCRIPT_DIR
- Handle Windows path separators correctly
- Set environment variables properly

## Troubleshooting Guide

### Common Issues
1. **Port 4200 occupied**: Force kill Prefect processes
2. **Module not found**: Check PYTHONPATH and conda environment
3. **Worker not starting**: Verify work pool exists and environment is activated
4. **Deployment fails**: Ensure server is running and API URL is correct

### Debug Commands
```bash
prefect server status
prefect work-pool ls
prefect deployment ls
conda list prefect
```

## Quick Start
1. Run `python register_flows.py` to initialize complete environment
2. Monitor terminal windows for server and worker status
3. Check Prefect UI at http://127.0.0.1:4200 for deployment status
4. Validate scheduled flows are executing as expected
